# Porting a documented UAC cluster

Use [SELECTION.md](SELECTION.md) first. One scenario is an integrated, source-backed chain for one UAC identifier on one OS. A command, tool family, or malware component by itself is a **stage**, not another cluster.

1. Record the primary CERT-UA advisory or original incident analysis, publication date, UAC identifier, observed OS, and actions actually described. Keep attribution confidence separate from the identifier.
2. Choose several connected, detection-relevant actions from the same incident. State the gap between original malware and the lab action in both language versions. Exclude behaviors whose platform is not documented.
3. Bound the run to the agent user and module-owned temporary directory. Clean up temporary scheduled tasks, systemd units, child processes, and decoy files. Do not read real user content or perform credential theft, external C2, lateral movement, production service changes, or disk destruction.
4. Create `modules/<cluster>-<os>/manifest.json` and `run.sh` or `run.ps1`. The manifest has `id`, `clusterId`, `platform`, bilingual title, description and limitations, primary source, dependency list, and ordered `flow` stages. Give each flow stage an `attack` field: `{ "id": "T1053.005", "mode": "emulated" }` when the lab performs a bounded version of the technique, `mode: "context"` when it only represents part of the technique, or `null` for lab infrastructure and unmapped artifacts. Check the ID against the [MITRE ATT&CK technique catalog](https://attack.mitre.org/techniques/). The script writes a compact `result.json` with boolean `phases` matching those stages and bounded metrics. The Linux server wrapper checks `requires` before execution; Windows scripts check their own dependencies first.
5. Run `python3 panel/modules/validate.py --run`, build the C++ server and React app, and inspect the result and cleanup. Windows live execution requires a Windows test agent; a Linux host can only validate manifest shape and, if installed, PowerShell syntax.
6. Run a task through the signed agent channel. Verify the task result, phase events, Attacks graph, and cleanup. An `ok` run proves the lab sequence executed; it does not prove a real EDR alert. Compare with EDR telemetry on the test host separately.
7. Run `python3 panel/modules/coverage.py --write`. Deploy only validated panel artifacts, restart only the panel service, and verify existing VPS web and CDN services still answer. Do not push the repository.

CERT-UA's [2025 overview](https://cip.gov.ua/en/faqs/cyber-threat-overview-and-defense-strategies-in-2025-cert-ua-s-experience) says more than 150 clusters were tracked. The exact current count is not stated there. `coverage.json` counts implemented IDs and scenarios only; it is not the complete UAC catalog.
